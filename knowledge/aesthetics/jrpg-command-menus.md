# JRPG Command Menus

## Scope and classification

A command-and-party interface grammar documented across Japanese role-playing games: named actions branch into inventories, abilities, equipment and character status while resource information stays organized. This descriptive catalog label spans blue console windows, parchment handheld menus and modern graphic interfaces. It does not claim that every Japanese game has one national visual style. Preserve navigable command hierarchy and explicit party state; raster pixels, blue gradients and portraits are branches rather than universal requirements.

This is a new canonical entry, screened against current catalog slugs, labels, aliases, redirects and subset names. 8-bit pixel describes raster construction; these menus survive beyond pixels. DVD Menu concerns authored disc navigation rather than party resources. Diegetic interfaces may situate controls inside a fictional world; JRPG menus are often explicitly outside it.

## Dimension Synthesis

### Palette

Dark blue/white console windows recur, but gray, cream, yellow, red and cyan systems are directly represented. Contrast separates selected command, resource values and help text; a single blue palette cannot define the whole corpus.

### Type

Short action labels, aligned resource abbreviations and strong numerical hierarchy. Older raster lettering and newer italic or condensed display systems coexist; avoid treating a pixel font as compulsory.

### Texture

Bounded window planes range from flat black/white through beveled gradients to paper and graphic collage. Keep ornamental texture subordinate to resource legibility.

### Shape

Rectangular command lists, nested selection windows, party slots and status meters dominate. Portrait circles, angled modern cutouts and parchment panels are documented variants.

### Motion

Inspected Final Fantasy menu videos show discrete selection, subpanel changes and character/status continuity. Their playback samples do not establish universal durations. Proposed web changes should be immediate, with optional brief panel transitions and an instant reduced-motion fallback.

### Spatial

A visible command tree beside party/resources and contextual explanations. Handheld dual screens distribute these roles across stacked surfaces; modern widescreen menus spread them across large panels.

### Cultural markers

Party membership, equipment, abilities, HP/MP-like resources and an explicit return path. Recognize individual game makers and eras rather than equating the grammar with Japanese culture as a whole.

## Analysis

### Claim-to-artifact support

Command/party/help hierarchy: JR1870, JR1899, JR1894, JR28-party, JR1207 and the survey. Palette/type counterexamples: JR72, JR1884, JR831, JR708. Motion: three grouped video records with timestamps in the ledger.

### Confidence and gaps

High confidence in command/party hierarchy, moderate in era-spanning texture, low in a single motion vocabulary. The corpus favors published English-language captures; exact font families and original timing are not inferred.

Core identity is limited to the supported traits in the canonical non-negotiables. Counterexamples have been incorporated into the guidance rather than discarded to make a uniform mood board. No still-derived exact motion timing, measured physical performance or unverified source claim is promoted to fact.

### Application handoff

Connotation mode: **contemporary revival**. Artifact concept: **Astral Company expedition inventory**. Signature visual unit: command window. Use an expedition inventory or equipment planner. Keep command buttons separate from resource readouts, show item quantities and disabled reasons, and update the selected character consistently. On narrow screens, place commands before party details and help in reading order. Native buttons work better than imitating an entire gamepad input system without its affordances.

These are **proposed application tokens**, not sampled historical colors or measured timings. ### Accessibility and adaptation flags

Palette tokens do not certify interface contrast. Check actual foreground/background states, focus outlines, disabled controls and overlays; target WCAG AA text and non-text requirements. Body text should remain 16px or larger in the application. Responsive priority is content order and control usability, not a tiny scaled facsimile. Keep explicit text equivalents for graphs and decorative SVGs hidden from assistive technology when captions already describe them. Respect user zoom and narrow layouts.

Reduced motion: stillness or immediate state changes are valid. Any proposed motion is optional, interruptible and removed for reduced motion. Dark mode: retain the artifact's deliberate material palette within its scoped frame; adapt surrounding application chrome separately. Fatigue: limit the loudest texture/type to the defining field. Conflict rule: preserve the non-negotiables and task semantics before introducing a neighboring palette, font or transition.
