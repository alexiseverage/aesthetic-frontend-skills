# Component Notes Contract

When `aesthetic-application` produces component guidance, cover these twelve component categories with one concrete implementation note each. Keep notes tied to tokens and canonical-entry dimensions.

| Component | Required note |
| --- | --- |
| Buttons | radius, border/fill behavior, hover/active motion |
| Cards | surface, shadow/depth, texture, internal spacing |
| Inputs | border, focus state, placeholder/type behavior |
| Navigation | density, active state, hierarchy, orientation |
| Hero/header | composition, type scale, visual anchor |
| Headings | display font/category, case, tracking, spacing |
| Dividers | line style, ornament, spacing role |
| Links | color, underline/decoration, hover behavior |
| Badges/tags | shape, fill, border, text treatment |
| Modals/overlays | backdrop, elevation, motion, containment |
| Alerts/notifications | color semantics plus aesthetic-preserving treatment |
| Icons | stroke/fill, geometry, motif boundaries |

If a component is irrelevant to the user's project, say so briefly and provide the nearest reusable pattern instead of inventing a component.
